# templates/

Templates for [cargo-generate], built around a **trunk + branches** model for
Linux applications: one program runs many subsystems concurrently (Embassy
async tasks on its standard executor).

- **Trunk** — the per-board project template. Builds the shared `Trunk` and
  starts every branch. Stays small.
- **Branch** — a subsystem module scaffolded by `bonsai branch <name>`,
  wired into the trunk automatically. Branches are board-portable.

## Layout

```
templates/
  _branch/
    branch.rs              # the branch scaffolds (consumer; branch_producer,
    branch_producer.rs     # branch_duplex, branch_roots) — baked into the
    branch_duplex.rs       # binary via include_str! so `bonsai branch` works
    branch_roots.rs        # anywhere. `{{branch_name}}` is a plain .replace,
                           # not Liquid.
    roots.rs               # the bridge every root shares; written to a tree's
                           # src/roots.rs by its first `branch --roots`.
  linux/
    <board>/               # a trunk project (cargo-generate template)
      cargo-generate.toml
      Cargo.toml
      .cargo/config.toml   # the build target and runner (none for host)
      bonsai.toml          # per-nutrient path shape + capacity (read by the CLI)
      src/
        main.rs            # trunk: starts the pulse, then branches
        trunk.rs           # the Nutrient vocabulary + the Trunk handle
        sap.rs             # GENERATED by `bonsai sync` — never edit by hand;
                           # declared inside trunk.rs (`#[path] pub mod sap`)
        pulse.rs           # built-in cycle of life (heartbeat + monitor)
        branches/
          mod.rs           # registry — empty, has the bonsai: markers
```

Boards covered: `linux/{zero-w,zero-2w,pi5,host}`. Each emits a Linux
userspace application, using Embassy's standard executor. There's no HAL: Linux
owns the hardware. A Pi template's `.cargo/config.toml` builds for the Pi, and
its runner copies the binary to the Pi over ssh (`BONSAI_PI`) and runs it
there; `cargo local` runs on the host. The `host` template sets no target, so
it builds and runs on the computer it's on.

## The branch contract

Every branch module exposes a `start()` that spawns its task. The trunk hands
out devices, so a branch that needs one takes it as an argument:

```rust
pub fn start(spawner: &Spawner, trunk: &Trunk /*, port: SerialPort */) {
    spawner.spawn(run(/* … */)).unwrap();
}

#[embassy_executor::task]
async fn run(/* … */) { loop { /* subsystem logic; await timers/events */ } }
```

`bonsai branch` inserts above two markers in **two files** — keep them intact:

```rust
// src/branches/mod.rs — the registry (starts empty)
// bonsai:mod           <-- new `pub mod <name>;` lines go here
```
```rust
// src/main.rs — the trunk, where branches are started and given devices
    pulse::start(&spawner, &trunk);   // built-in cycle of life (pulse.rs)
    // bonsai:start      <-- new `branches::<name>::start(&spawner, &trunk);` calls go here
```

`insert_before_marker` in the CLI matches the marker as a whole line, so a doc
comment mentioning `// bonsai:mod` in prose won't be mistaken for it.

The **pulse** (`src/pulse.rs`) is core trunk plumbing, not a branch: a heartbeat
that releases a `Beat` into the sap and a monitor that prints each beat. It's
identical on every board.

**`src/sap.rs` is generated.** The CLI renders it from the template's own
`trunk.rs` + `pulse.rs` + `bonsai.toml`. After changing any of those in a
template, run `bonsai sync` inside `templates/linux/<board>/`. The
`template_sap_matches_generator` test fails if a board's copy is stale. It
contains no Liquid, so cargo-generate passes it through untouched.

## Variables in a trunk template

Passed by the wizard via `-d`: `chip` and `board` (`template_defines` in
`src/main.rs`, from `BOARDS`). Built in by cargo-generate: `project-name`,
`crate_name`. Each template stamps its board and chip into `Cargo.toml`
(`# Generated by bonsai for <board> (<chip>)`); `regrow`, `update`,
`retarget` and `tools` read the board back from it.

## Adding a board

1. Add it to `BOARDS` in `src/main.rs`.
2. Create `templates/linux/<board>/` — copy an existing board's trunk and
   adjust the target bits (`Cargo.toml`'s stamp and profile,
   `.cargo/config.toml`, the first doc line of `src/main.rs`).
   The `src/branches/`, `src/trunk.rs` and `bonsai.toml` files are portable;
   reuse them as-is, then run `bonsai sync` in the new directory to generate
   its `src/sap.rs`.

## Rendering

Every file passes through [Liquid], so `{{ project-name }}`,
`{% if board == "pi5" %}...{% endif %}`, etc. work. The branch scaffold
(`_branch/branch.rs`) is *not* rendered by cargo-generate — the CLI does a
plain `{{branch_name}}` substitution when you run `add branch`.
