# {{project-name}}

Device firmware for **{{board}}** (`{{chip}}`), generated by bonsai.

Built as a **trunk + branches**: `src/main.rs` (the trunk) brings up the
hardware, starts the built-in *pulse* (its cycle of life), then your branches.
Each subsystem lives under `src/branches/` and runs as an Embassy async task.

```
src/
├── main.rs            # trunk: HW init, starts the pulse, then branches
├── trunk.rs           # the Nutrient vocabulary + the Trunk handle
├── sap.rs             # GENERATED by bonsai: one channel per nutrient
├── pulse.rs           # built-in cycle of life (heartbeat + monitor)
└── branches/
    └── mod.rs         # registry — empty; your subsystems go here
```

## Grow the device

```sh
bonsai branch imu        # scaffolds src/branches/imu.rs and wires it in
bonsai branch telemetry
```

## Prerequisites

```sh
rustup target add {{target}}
cargo install probe-rs-tools
```

## Build & run

```sh
cargo build --release
cargo run --release            # flashes via `probe-rs run --chip {{probe_chip}}`
```

For a lean production image, drop panic messages (about half the flash — a
panic still halts, and `probe-rs` still prints its backtrace):

```sh
cargo build --release --no-default-features
```

## Next steps

- `cargo run` should stream the pulse over RTT — `bonsai: beat` every half-second.
- Wire real I/O: rename `_p` → `p` in `src/main.rs` and hand a branch a pin
  (the on-board LED is `PIN_25` on Pico / Pico 2; on the wireless boards it's on
  the CYW43 chip instead).
- Branches share nutrients through the sap: one channel per nutrient, generated
  into `src/sap.rs`. Add your own with `bonsai feed`, wire them with `bonsai tap`
  / `bonsai release`, and see the flow with `bonsai list`.
